    What does this click cover?

    Reading a click

    Every row is one click — or one marked step — with every request and query it caused. Open it and read it top to bottom:

    1. Verdict. Why it took as long as it did: database-bound, application-bound, mostly between requests, or fast.
    2. Where the time went. The wait, split into SQL, application code and the gaps between requests. Measured, not estimated.
    3. Fix first. The query groups worth changing, ranked by the time a fix would buy back, with the method and line to open. Savings are estimates: removable executions × their average duration.
    4. Waterfall. Each request on a time axis, with every query as a tick in it. A wall of ticks is a loop; click one to jump to its query group.
    5. Queries. Every query group, unfoldable to its findings, call paths, SQL and each execution.

    The verdicts

    Database-boundHalf or more of the server time is SQL. Fixing queries makes this click faster.
    Application-boundMost server time is outside the database — code, serialisation, other services, locks. Removing queries will not fix it; profile the endpoint.
    Between requestsThe server was idle most of the time: the browser was rendering, or requests waited on each other.

    The numbers

    Every query listed is a real database round-trip. Reads answered from the change tracker never reach the database and never appear here.

    QueriesEvery SQL statement. One batched command counts once per statement inside it.
    RepeatsThe same query with the same values repeated inside one request, plus N+1 loops collapsed to a single query. The real target — fixable in one method.
    Dup. writesThe same row written more than once with the same columns, so the second write throws the first away.
    Cross-requestThe same query in different requests of one click. Each request has its own unit of work, so this is usually normal; removing it is a design decision and it is not counted as removable.
    After fixesqueries − repeats − dup. writes
    At 10× dataWhat the same clicks would cost against ten times the data. Only proven growth is scaled; a range means a loop inside a loop.
    DB timeThe sum of each command's own duration — not wall-clock time.
    Not waitedDB time from calls after the response was sent, or outside any request. A write there is flagged: the user was told “success” before it ran.
    In loopThe query's call site is flagged by a static analysis report as a database call inside a loop — see Settings.

    Settings

    Recording

    Comma separated. The browser extension only tags calls going to these ports.

    Static analysis

    Optional. A report of loops whose body reaches the database — a findings list or a SARIF file from a Roslyn analyser. Queries whose call site it flags get an in loop badge that names the loop. Read in place and re-read when the file changes; never copied.

    When to flag something

    Saved recordings keep the raw commands, so changing these re-judges everything you already have — nothing has to be recorded again.
